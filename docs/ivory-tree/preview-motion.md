# 纸签预览动效

## 运动规则

预览从纸签挂点展开，纸面轮廓、正文和缩略内容共用一条空间路径。展开、收回和中途换向都使用 SwiftUI `Spring(duration: 0.32, bounce: 0)`。该值是弹簧响应参数，不是强制在 320 ms 结束：从静止开始约 240 ms 完成 95% 位移，剩余部分继续减速。所有几何通道的位置误差低于各自阈值且速度足够低时才交回真实视图；宽高和位置阈值为 0.24 pt。

“开合一致”指相同纸面、挂点路径、弹簧参数和镜像位移/速度。它不是将展开影片逐帧倒放：倒放减速段会变成加速段，无法同时保证连续输入时自然接续的速度。两端都从静止起步并减速落稳，中途输入继承位置和速度；新目标可以立即改变加速度，不强行延续上一次指令的制动力。

动画只有一个持续存在的状态和显示时钟。换向只替换目标及最终回调，不重新捕获同一记录的纸面、不重启时钟、不把剩余距离塞进一个新的短时长。方向键换记录时更新两张内容快照，沿当前位置继续移动，阅读尺寸保持不变。纸签布局稍晚更新时再次核对实际挂点，只更新运动目标；不能把第一次收到选择通知时的位置当成最终位置。

`MotionClock` 使用 `CADisplayLink.targetTimestamp` 采样下一呈现帧的位置，避免主线程回调到达时间变化造成步幅不均。纸面仍通过 AppKit 的局部窗口呈现，未添加覆盖桌面的输入窗口；使用原生 Spring 求解不等于把整个窗口动画交给 Core Animation。

## 为什么替换旧规则

旧实现完整开合用有限时长 cubic ease，打断后切换为自定义三阶响应，并保留加速度。中等频率输入时，两种运动规则的区别比单次播放更明显。新实现删除自定义积分器、限速函数和第二套折返参数，完整动作和折返不再切换动力学。

同纸面比较覆盖完整开合、100 ms / 200 ms 连按及正常速度 / 四倍慢放。模型采样中，100 ms 连按两版的换向时间接近；200 ms 连按新版约 4–5 ms、旧版约 7–11 ms。该指标只描述开始回转的时间，不代表端到端延迟，也不能单独证明观感流畅。

## 边界与验收

- 开合使用同一渲染器，图像等比、正文不横向拉伸，内容交接取决于纸面几何而非开合方向。
- 快速输入和 50–300 ms 多种间隔验证位置、速度连续、无旧回调补播、无越界回弹；60/120 Hz 路径一致。
- 减少动态效果继续使用 120 ms 的有限淡入淡出。
- 搜索、键盘选择、图片/OCR、同次预览缩放、关闭复位、原生内容拖拽和局部窗口命中规则保持独立回归。
- 代码与逐帧检查不能代替用户正常速度下的观感验收；截图也不能证明合成器的帧节奏。

## 依据

Apple 的 [Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/) 和 [Spring](https://developer.apple.com/documentation/swiftui/spring) 支持无回弹响应、按位置/速度接续以及独立求解；[Motion HIG](https://developer.apple.com/design/human-interface-guidelines/motion) 强调有目的、克制并尊重交互的运动。这里的 0.32 是本产品的选择，不是 macOS 或 Quick Look 的统一规范，也不声称复制了系统内部实现。
