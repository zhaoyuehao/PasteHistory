PasteHistory · Redesign Brief

它不管理历史。
它记得你手上正拿着什么。

乔布斯会做的第一件事，是删掉 "History" 这个词。第二件事，是让大部分时候根本不需要打开面板。

「简单可以比复杂更难：你必须让自己的想法干净到极点，才能让它简单。」
01 — 三个判断

先定产品，再谈界面

✂️

它是剪贴板，不是档案馆

「历史」是归档思维：列表、筛选、计数、来源、时间戳。但用户 99% 的场景是「我 30 秒前复制的东西，现在还给我」。这是拿取，不是检索。产品定位一句话：系统剪贴板，只是它有记忆。

→ 面板里一切"档案味"的元素都要杀
⭕

最好的 UI 是没有 UI

为「30 秒前的一条」开一个 720×460 的窗口、再读五个快捷键提示，是羞辱。新增 ⇧⌘V 循环粘贴：按一下贴最近一条，再按撤销换成上一条。零界面、零焦点切换、零搜索。面板只在「找」的时候出现。

→ Layer 0 消灭 80% 的开窗次数
🤫

别解释自己在干什么

字符数、来自哪个 App、iCloud 小圆点、底部五个 hint——这些是写给工程师看的状态面板。同步要么成功、要么你不提；失败时才说一句话。软件的存在感越低，信任感越高。

→ 界面里所有"元信息"默认删除
02 — 减法清单

对现有 UI 逐元素审判

乔布斯的方法论从来不是「加什么」，而是「不做什么」。下面是当前 HistoryView.swift 里每一个可见元素的判决。

元素（现状）判决理由
底部快捷键提示条（5 个 hint）杀说明书不是 UI。快捷键在用户按对一次之后就学会了；学不会的人看提示条也学不会。
独立预览窗格（双栏布局）杀最狠也最对的一刀。预览是文件管理器思维——你刚复制过它，你记得它长什么样。改为选中行就地展开，面板从双栏收成单列、从 720 宽收到 520。
类型筛选分段（全部/文本/图片/文件）杀类型差异内容自己会表达：图片就是缩略图，文件就是图标。搜索框已经能过滤。多一个控件就是多一个让用户思考的岔路口。
"文本/图片/文件" 彩色类型徽章杀彩色标签是分类系统的味道。现在有橙（置顶）、粉（图片）、绿（文件）、蓝、黄（高亮）五种强调色——太杂。全界面只允许一种强调色。
"128 / 3,481" 计数器杀用户不需要知道自己有几千条。知道这个数字不会让任何一条更容易找到。
字符数 · 行数统计杀同上。
iCloud 状态圆点 + "已同步"杀同步是承诺，不是新闻。只在失败时说话：菜单栏出现一项「同步中断 · 检查网络」。
预览头部"复制/置顶"按钮折叠复制已由 ⇧⌘V 和 ⌘C 覆盖。置顶降级为行内 hover 时出现的图钉图标——高频动作配快捷键，低频动作不占空间。
三条 Divider + 竖分割线折叠分割线是「我没想清楚层级」的表现。用留白和对比区分层级，只保留搜索区下一条 0.5px 细线。
列表行 3 行摘要收窄1 行能扫 20 条，3 行只能扫 8 条。密度就是速度。想看全文？选中它就地展开。
⌘1–9 快速粘贴角标留这是「可见的承诺」——像 Dock 图标上的角标。它每天教用户一遍肌肉记忆，是界面里最值得保留的元信息。
图片 OCR 文字留全产品最乔布斯的功能：让「搜索截图里的文字」成真。展开的图片条目下保留一行 OCR 摘要。它会出现在 Keynote 的 demo 页上。
空状态留 + 重写搜不到不要说「没有匹配的内容，换个关键词，或切回全部筛选」。说「没找到。」然后闭嘴。
03 — Layer 0

⇧⌘V：在时间轴上擦，不用打开任何窗口

06 — 规范

四条硬规范

一种强调色全界面只允许 #0071E3。选中、链接、焦点线共享它。其余全部是灰阶。现在的橙/粉/绿/黄全部退役。
零分割线层级用留白和字重表达。整个面板只保留搜索区下一条 0.5px 细线。圆角统一 14（窗）/ 8（行）/ 10（图）。
密度即速度正文 13px，次要 10.5px。列表行单行摘要，默认一屏 ≥ 12 条。选中行就地展开，最多 10 行可滚动。
物理反馈每次 ⌘C 捕获，菜单栏图标做 0.3s 的「点头」微动画——不弹通知、不出声音。你感到它被记住了，仅此而已。
07 — 交互规格

动画时长与曲线，一个都不能猜

乔布斯对动画的要求不是「好看」，是诚实：动画必须告诉用户东西从哪来、到哪去。所有动效都在 0.3 秒内结束——超过 0.3 秒，用户就开始等待。

交互时长曲线 / 说明
面板出现0.22seaseOut；opacity 0→1 + scale 0.96→1。不要从 0.9 起步——那是表演，不是出现。
面板消失0.15seaseIn，只做 opacity，不缩放。缩小消失会读出「弹回」，廉价。
粘贴后面板消失0.12sopacity only。用户要的是「它没了」，不是「它表演了没」。
选中态切换0.15seaseOut。只是背景色，必须比内容变化快一档，否则选中感滞后于手感。
就地展开 / 收起0.30sspring(response: 0.30, dampingFraction: 0.86)。弹簧给物理感，0.86 的阻尼保证不回弹过头。
↑↓ 单次移动0.20seaseOut，跟随滚动。比展开短一档：移动是轻动作。
↑↓ 连按（间隔 < 200ms）无动画长按方向键时，0.30s 的弹簧会堆积成迟滞。速度必须让位：Transaction(animation: nil)。这一条决定手感。
搜索结果刷新0.18seaseOut，列表整体 opacity 淡入。不做逐行 stagger——那是舞台效果，不是工具。
删除一条0.24s行高→0 与 opacity→0 同步，下方行上移用同一条曲线。不做确认框：删除应该飞走，不应该请示。
菜单栏点头（捕获成功）0.30sscale 1→1.15→1，easeInOut。不弹通知、不出声。你感到它被记住了，仅此而已。
08 — 尺寸规格

每个区域的确切数值

单位 pt。窗口 520 × 540，固定，不可 resize——工具不是家具，不该让用户承担调尺寸的责任。

区域数值理由
窗口520×540宽 520 放得下 30 个中文字符，眼球横向移动距离最短；高 540 保证一屏可见 12 条收起行，或 1 条展开 + 4 条收起。
窗口圆角14macOS 窗口标准。行 8，缩略图 8，大图 10，角标 5——四级，不多一级。
搜索区高 5215px 字 ×2 + 上下留白。它是头部，必须比列表「重」一点，否则压不住。
搜索区左右内边距18比列表行的 12 更宽，制造层级差——不用分割线也能分出头与体。
搜索分隔线0.5px全界面唯一一条线。未聚焦灰，聚焦时染 #0071E3。这是唯一的「焦点」表达。
列表外边距左右 6让选中态的圆角块不贴窗边，有呼吸。
行内边距左右 126 + 12 = 18，与搜索区文字左边缘严格对齐。
收起行高4434 缩略图 + 上下 5 留白。44 同时是 Apple 最小点击区——这不是妥协，是巧合得刚刚好。
行间距2紧到看得出是同一列，又不会糊成一片。3 条分割线换成 2pt 的空气。
缩略图34×34圆角 8。纯文本类型不画图标，用 34×34 的浅色底块 + 17×17 字形。
缩略图 ↔ 文字12与行内边距同值，网格一致。
展开行内边距13比收起多 1，让展开块看起来「鼓」出来一点。
展开大图高 240上间距 10，圆角 10。240 是「图看得清」与「下面还剩 2 条可见」的平衡点。
OCR 行12px上间距 9。标签三级色、内容二级色，靠颜色分级而不是靠字号。
展开区上限240文本超出即内部滚动。窗口不 resize，展开只在窗口内部长高。
选中态8%#0071E3 @ 8%，圆角 8，没有左侧竖条。竖条是「未选中行也需要对齐」的补丁，说明布局本身没对齐。
⌘N 角标高 18左右内边距 5，圆角 5，mono 11。右边缘与文字右对齐。

10 — 让动画真的流畅

SwiftUI 上会翻车的七个点

规格写得再漂亮，这七条不做，落地就是「理论流畅」。

1 · 展开必须是几何动画，不是结构动画别写 if selected { Detail() }——视图插入/移除走的是 appear/disappear 路径，macOS 上表现为瞬变。改成内容常驻：frame(height: selected ? h : 0) + clipped() + opacity()，让高度成为连续量。
2 · 动画绑在值上，不用全局 withAnimation.animation(.spring(...), value: selected) 加在 row 内部。全局 withAnimation 会连带波及滚动，出现「展开 + 列表一起动」的糊状感。
3 · 滚动别用 anchor: .center现在 scrollTo(id, anchor: .center) 每按一次都把选中行拉到正中，整片列表跟着滑——这是「抖」的根源。改成只在选中行超出可视区时才滚，且滚最小位移（anchor: nil，或算 offset 用 contentView.animator().setBoundsOrigin）。
4 · 连按必须去动画记上次 move 的时间戳，间隔 < 200ms 时套 Transaction(animation: nil)。长按 ↓ 的时候，这一条比曲线参数重要十倍。
5 · 图片先解码再展开选中前异步按 2× 显示尺寸预缩放并缓存，否则展开动画的第一帧是空白。DB 里已有 128px 缩略图，先拿它上采样顶住第一帧，原图到位后 0.12s crossfade。
6 · 窗口不参与动画高度固定 540，展开时窗口不 resize。窗口尺寸动画与内容高度动画同时跑必然打架——这正是我砍掉「弹性窗口高度」的原因。
7 · 面板出现只用一套时序NSWindow.animator().alphaValue 做淡入，内容 scale 交给 SwiftUI 的 transition，二者必须同一 duration（0.22s）。两套时序叠加会出现「先亮后弹」。
8 · 键盘事件走 localMonitor 但别阻塞现有 addLocalMonitorForEvents 是对的。注意 return nil 吞掉事件后，连按的 repeat 事件仍会到达——去动画的判断要放在这里，不是放在 View 里。
